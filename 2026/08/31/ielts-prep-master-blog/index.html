用 Python + PyQt6 造一个雅思备考桌面应用：从背单词到真题模考的全栈实现

一、为什么要自己造轮子

备考雅思那段时间，我试了市面上不少背单词和模考软件，痛点很集中：广告多、词库不能自定义、听力阅读模考必须联网、学习数据存在别人服务器上。我想要的其实很简单——一个纯本地运行、零广告、数据完全自己掌控的桌面工具，能背单词、能模考听力阅读、能看学习统计。

既然找不到合适的，那就自己写一个。于是有了 IELTS Prep Master（雅思备考助手）：一个基于 Python + PyQt6 的桌面应用，覆盖词汇闪卡、听力真题模考、阅读模考、学习统计四大模块，打包成单 exe 后双击即用，所有数据存在本地 SQLite 里。

二、技术选型与整体架构

为什么是 PyQt6 而不是 Electron 或 Web 端

方案 优点 放弃原因
Electron 生态成熟、界面灵活 打包体积动辄 100MB+，内存占用高
Web 端（Flask/Django） 开发快 需要起服务、开浏览器，违背”双击即用”的初衷
PyQt6 原生性能、Python 生态好接 AI/数据处理、打包体积小 学习曲线略陡

最终选了 PyQt6。SQLite 作为本地存储——单文件、零配置、不需要装数据库服务，太适合桌面应用了。PDF 渲染用 PyMuPDF（fitz），打包用 PyInstaller。

项目结构

主窗口架构

主窗口用 QMainWindow + 左侧固定侧边栏 + 右侧 QStackedWidget 页面堆栈。四个模块各是一个独立的 QWidget，通过侧边栏按钮切换索引。

导航按钮的高亮用了 QSS 动态属性，这里有个 PyQt6 的坑后面会讲。

三、核心模块一：词汇闪卡与 SM-2 间隔重复算法

这是整个项目技术含量最高的部分。背单词的核心不是”展示单词”，而是什么时候该复习。我用了 SuperMemo 2（SM-2）间隔重复算法——Anki 用的也是这套算法的变体。

数据库设计：SRS 所需的四个关键字段

四个字段配合工作：repetition 记录连续答对几次，interval 根据 repetition 和 ease_factor 计算出下次复习间隔，ease_factor 会根据用户的掌握程度动态调整。

SM-2 算法核心实现

用户每张卡片评分后（quality 0~5，>=3 算认识），调用 update_word_sm2：

算法逻辑很清晰：

  • 前两次答对用固定间隔（1天→6天），建立基础记忆
  • 第三次起间隔 = 上次间隔 × ease_factor，指数级增长
  • 答错直接重置，repetition 归零、间隔回到1天
  • ease_factor 动态调整：quality=5 时 +0.1，quality=3 时 -0.14，quality=0 时 -0.8，最低不低于1.3

四、核心模块二：听力真题模考与自动评分

听力模块是我用得最多的功能。左边渲染剑桥雅思真题 PDF，右边是 1~40 题答题卡，做完提交后自动判分并换算 Band 分数。

双图层设计的好处是标注和原图完全分离——清除标注只需要把 overlay 图层填回透明，不会损伤原图。另外 map_to_pixmap 方法处理了显示缩放后的坐标映射，确保在不同窗口大小下标注位置都准确。

自动评分：多答案 + 前缀匹配

雅思听力的答案判分有个麻烦之处：标准答案经常有多个可接受答案（比如 restaurant/cafe），而且数字/字母类答案用户可能多写了标点（比如答案是 A，用户填了 A.）。我的评分逻辑处理了这两种情况：

归一化（.strip().lower()）处理了大小写和首尾空格；re.split(r"[/|]") 处理了 restaurant/cafe 这种多答案；startswith 处理了 A vs A. 这种标点冗余。

五、核心模块三：阅读模考与学习统计

阅读模考

阅读模块复用了听力的 PDF 渲染 + 答题卡 + 评分框架，区别在于 Band 换算标准不同（阅读 Academic 的分数曲线比听力略陡），以及题型更丰富（选择题用单选按钮渲染，填空题用输入框）。

六、工程化细节与踩坑记录

坑1：PyInstaller 打包后所有路径都乱了

这是桌面应用打包最经典的坑。源码运行时 __file__ 指向项目目录，但打包成 exe 后 __file__ 指向临时解压目录，数据库和资源文件全部找不到。

解决方案：统一用 get_base_dir() 判断运行环境：

所有文件路径（数据库、图标、词库、真题 JSON）都走 get_resource_path()，打包后把资源文件放在 exe 同级目录即可。

坑2：数据库表结构迭代怎么办

开发过程中词汇表加了好几个字段（translation、is_mastered、status），如果直接改 CREATE TABLE，老用户的数据库会因为列不存在而报错。我的做法是自动迁移：

CREATE TABLE IF NOT EXISTS 建表 + ALTER TABLE ADD COLUMN 补列 + try/except 吞掉”列已存在”异常，老用户升级后首次运行自动补全字段，不丢数据。

坑3：PyQt6 动态属性样式不刷新

侧边栏导航按钮的高亮用了 QSS 动态属性 [active="true"]，但改了 setProperty 后样式不会自动刷新，必须手动 unpolish + polish：

这个坑卡了我半小时，网上很多 PyQt5 教程没提这个细节。

坑4：PDF 渲染方案选型

最初试过在 QLabel 里实时用 fitz 渲染当前页，但翻页时卡顿明显。最终改成预转图片序列（用一个独立的 PDF 转换工具批量导出），运行时只做 QPixmap 显示，翻页流畅度提升明显，打包体积也更小。

七、效果与后续规划

目前四个模块都能正常使用：词汇模块跑 SM-2 算法安排复习，听力和阅读模块支持真题模考+自动评分，统计模块记录打卡和进度。PyInstaller 打包后是一个 exe + 一个 db 文件 + 资源目录，拷到任何 Windows 机器上双击就能运行。
