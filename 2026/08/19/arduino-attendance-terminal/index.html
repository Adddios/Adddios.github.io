基于 Arduino Mega 2560 的智能考勤终端设计：多串口协同与网络时钟同步

发表于2026-08-19|更新于2026-08-19|项目实战
|浏览量:

这是我实习期间完成的第一个硬件小项目。简单来说，就是用一块 Arduino 搞定“扫码枪 + 串口屏 + 以太网模块”的联调，做一个能扫码考勤、显示结果并自动校时的终端设备。记录一下开发过程
一、 任务需求与硬件选型
扫码：员工用扫码枪刷二维码。
上报与显示：Arduino 把扫码内容发给服务器，服务器返回考勤结果（成功/失败/重复等），并在屏幕上显示对应的颜色和文字。
显示时间：屏幕上要实时显示当前时间，并且能定时跟服务器同步最新时间。
在 setup() 里先把各个串口初始化好，顺便向服务器发一个开机校时请求：
void setup() {
// 初始化各个硬件串口
Serial.begin(115200); // 调试串口（电脑）
Serial1.begin(115200); // 串口屏
Serial2.begin(115200); // 以太网模块
Serial3.begin(115200); // 美松扫码枪

// 开机向服务器拉取一次时间
Serial2.print("timeAdjust\r\n");

}

为什么选 Arduino Mega 2560？
因为这个项目需要同时连接 3 个串口外设：
1.淘金池串口屏（接 Serial1）
2.塔石以太网透传模块（接 Serial2）
3.美松扫码枪（接 Serial3）
普通的 Arduino Uno 只有一个硬件串口，用软串口（SoftwareSerial）容易丢包或不稳定。而 Mega 2560 自带 4 个硬件串口，直接拿来搞定多外设通信，省去了很多麻烦！

二、 核心逻辑
整个系统的运作流程可以拆分成三步：

[扫码枪] –(Serial3)–> [Mega 2560] –(Serial2)–> [以太网/服务器]
[串口屏] <–(Serial1)– [Mega 2560] <–(Serial2)─────────┘

1.扫码透传：
通过 serialEvent3() 监听扫码枪，只要扫到条码（以换行符结尾），就原封不动地发给以太网模块送到服务器。
2.结果处理：
服务器收到后会返回一个状态码（比如 1 代表成功，2 代表失败）。Arduino 收到后，给串口屏发指令改变文字和背景颜色，并在 3 秒后自动清空。
3.本地时间自增 + 网络校时：
为了不频繁打扰服务器，本地用 millis() 定时器每秒自增时间，并在屏幕上更新时间显示；同时开机和每隔 12 小时主动向服务器拉取一次最新时间进行校准。

三、核心功能代码切片

  1. 扫码数据接收与“透传”给服务器
    美松扫码枪扫描到二维码后，会自动通过串口发送字符串（以 \r 或 \n 结尾）。这里利用 Arduino 的串口中断事件 serialEvent3() 异步接收，扫到后立刻转发给以太网模块：
    // 异步监听 Serial3 (扫码枪)
    void serialEvent3() {
    while (Serial3.available()) {
    char inChar = (char)Serial3.read();

    // 遇到换行符说明一帧数据接收完毕
    if (inChar == ‘\n’ || inChar == ‘\r’) {
    if (qrBufferIndex > 0) {
    qrBuffer[qrBufferIndex] = ‘\0’; // 加上字符串结尾符

    // 【核心逻辑】：将扫码数据直接透传给服务器
    Serial2.print(qrBuffer);
    Serial2.print(“\r\n”);

    qrBufferIndex = 0; // 重置缓冲区指针
    }
    } else {
    if (qrBufferIndex < sizeof(qrBuffer) - 1) {
    qrBuffer[qrBufferIndex++] = inChar;
    }
    }
    }

}
2. 解析服务器返回 & 更新串口屏 UI
服务器收到扫码数据后，会返回对应的考勤状态码（如 1 成功、2 失败等）。Arduino 接收到指令后，向串口屏发送带页面前缀（如 page2.t0.txt）的文本与颜色指令：
// 根据服务器返回的状态码更新屏幕显示
void updateDisplayStatus(char status) {
switch (status) {
case ‘1’: // 考勤成功
Serial1.print(“page2.t0.txt="考勤成功"\xFF\xFF\xFF”);
Serial1.print(“page2.t0.pco=2016\xFF\xFF\xFF”); // 绿色字体
break;

    case '2': // 考勤失败
        Serial1.print("page2.t0.txt=\"考勤失败\"\xFF\xFF\xFF");
        Serial1.print("page2.t0.pco=63488\xFF\xFF\xFF"); // 红色字体
        break;
        
    case '4': // 请勿重复扫描
        Serial1.print("page2.t0.txt=\"请勿重复扫描\"\xFF\xFF\xFF");
        Serial1.print("page2.t0.pco=65504\xFF\xFF\xFF"); // 黄色字体
        break;
}

// 标记当前正在展示结果，记录开始时间
showingResult = true;
displayStartMillis = millis();

}
注：串口屏指令结尾的 \xFF\xFF\xFF 是淘金池/大联屏等串口屏的标准结束符。
3. 抛弃 delay()！用 millis() 搞定定时任务
如果在单片机里用 delay(3000) 来等待 3 秒清屏，这 3 秒内整个系统都会“死机”，无法响应扫码。所以我采用了 millis() 轮询非阻塞设计：
void loop() {
unsigned long currentMillis = millis();

// 1. 每隔 1000ms 本地秒数自增，并同步给屏幕
if (currentMillis - lastClockMillis >= 1000) {
    lastClockMillis = currentMillis;
    updateLocalTime(); // 自增秒/分/时
}

// 2. 考勤结果在屏幕上停留 3 秒后，自动恢复空空闲状态
if (showingResult && (currentMillis - displayStartMillis >= 3000)) {
    showingResult = false;
    // 清空 page2 页面上的提示文字
    Serial1.print("page2.t0.txt=\"\"\xFF\xFF\xFF");
    Serial1.print("page2.t1.txt=\"\"\xFF\xFF\xFF");
}

// 3. 每 12 小时主动向服务器拉取最新时间（校时）
if (currentMillis - lastSyncMillis >= 43200000UL) {
    lastSyncMillis = currentMillis;
    Serial2.print("timeAdjust\r\n");
}

// 处理以太网接收的数据...
readEthernetData();

}

四、串口屏 UI 界面设计与“屏端”小技巧
界面使用了 USART HMI 软件进行开发（硬件型号：TJC8048IS543_011，4.3 寸分辨率 800x480）。

▲ 图 1：USART HMI 串口屏工程界面与屏端定时器脚本

串口屏内部定时器（tm0）减轻 Arduino 负担
在设计时间显示逻辑时，我没有让 Arduino 频繁组装 “10:30:00” 这种复杂的字符串发给屏幕，而是采用了一种逻辑解耦的巧妙设计：
Arduino 只传数字：Arduino 只负责把最新的时、分、秒数值推送到串口屏的全局变量 rtc3、rtc4、rtc5 中。
屏端定时器自主刷新：在串口屏里添加一个定时器控件 tm0（设置为 400ms 触发一次），利用串口屏自带的类 C 脚本自动完成格式转换和拼接：
// USART HMI 屏端事件脚本 (tm0 定时器)
// 1. 格式化转换：将数字转换为 2 位字符串 (如 8 -> “08”)
covx rtc3, va0.txt, 2, 0
covx rtc4, va1.txt, 2, 0
covx rtc5, va2.txt, 2, 0

// 2. 字符串拼接刷新到文本框 t2
t2.txt = va0.txt + “:”
t2.txt = t2.txt + va1.txt
t2.txt = t2.txt + “:”
t2.txt = t2.txt + va2.txt
这样设计不仅大大减少了串口通信的波特率占用，也让 Arduino 可以专注于扫码与网络通信。
