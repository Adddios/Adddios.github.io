基于 ESP32-S3 的离线边缘 AI 人脸识别与 Web API 管理系统

发表于2026-08-24|更新于2026-08-24|项目实战嵌入式开发
|浏览量:

开始我想着用 ESP-IDF + ESP-WHO 搞个离线人脸识别，结果拿第三方 ESP32-S3 板子适配 OV5640 时直接掉坑了。在 sdkconfig 和 CMake 报错里折腾了整整两周，各种依赖死锁。然后放弃了ESP-IDF转Arduino IDE当场就跑通了。。。
以下正文
系统底层直接跑 FreeRTOS 双核多线程。Core 0 专门留给后台 aiTask 任务，独立跑乐鑫的 MSR01+MNP01 人脸检测模型以及 FaceRecognition112V1S8 特征提取算法，完全不会卡顿 UI。Core 1 则负责摄像头抓帧、LovyanGFX 屏幕渲染和 WebServer 响应，两边用互斥锁保证推理结果和 NVS 存储的数据一致。

为了提高侧脸识别率，我写了个正脸到左脸再到右脸的三姿态防抖录入状态机，每个姿态倒计时 3 秒，提取到的特征最终全都绑定到同一个 Group_ID 上。后台内置了 WebServer，暴露 /api/status、/api/list、/api/rename 这些 RESTful 接口，方便在网页端远程看状态或者重命名用户。UI 渲染这块，用 roundf() 做了 1.5 倍精细化坐标映射解决关键点错位，再加了个 0.35f 衰减系数的 SmoothBox 差值算法，直接消除了人脸框在屏幕上乱抖的问题。

从技术实现来看，整个系统基于 ESP32-S3 (N16R8) 实现了完全脱离云端的本地离线人脸识别。硬件上通过 SPI 总线驱动 ST7735S 屏幕实时显示，配合 NVS 实现人脸特征的掉电持久化存储。软件架构采用 FreeRTOS 双核异步设计，Core 0 专门跑 aiTask 线程处理 MSR01+MNP01 检测模型和 FaceRecognition112V1S8 特征提取，Core 1 则负责摄像头抓帧、LovyanGFX 图像渲染和 Web 响应，两核通过互斥锁保证推理与存储数据的同步安全。

算法与业务层面上，重点解决了识别率与显示交互体验。设计了“正脸-左脸-右脸”三姿态防抖录入状态机，将多角度特征码绑定至同一个 Group_ID，大幅提升了侧脸与复杂角度下的比对成功率。系统同时嵌入了 RESTful Web 控制后台，暴露 JSON 接口支持远程查询、ID 合并与用户重命名。在 UI 渲染上，使用 roundf() 做了 1.5 倍精细化坐标映射解决关键点错位，并引入 0.35f 衰减系数的 SmoothBox 差值算法，消除了人脸框在屏幕上的抖动问题。

为了让这套硬件终端用起来更方便，我用原生 HTML5、CSS3 和 JavaScript 写了一个响应式 Web 控制后台。界面整体采用卡片布局，使用 #0f172a 主背景搭配 #1e293b 卡片背景，包含 IP 连接控制、实时状态监视、人脸特征库管理以及快捷指令控制面板。 前端通过 localStorage 记住输入的 ESP32 设备 IP，连接成功后开启 1000ms 的定时轮询调用 /api/status。

这里做了一个状态监听：当轮询检测到系统从“正在录入多姿态人脸”状态（d.e 为 true）切换回普通状态时，前端会自动触发 Toast 提示并无感刷新人脸库列表。 在人脸库管理方面，前端把后台传来的数据按 gid 进行分组展示。用户不仅可以在网页上直接修改对应 gid 的姓名并通过 /api/rename 保存，还能勾选多个特征 ID 实时调用 /api/merge 进行跨 ID 特征合并。针对个别人脸组的删除或者整个特征库的清空，分别挂载了 /api/deleteGroup 和 /api/clear 接口。此外，快捷面板还支持一键远程触发多姿态录入（/api/enroll）和软重启设备（/api/reboot）。
